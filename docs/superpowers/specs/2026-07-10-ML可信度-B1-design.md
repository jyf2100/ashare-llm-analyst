# ML 可信度（方向 B1·修数据泄露）设计

- **日期**：2026-07-10
- **状态**：待审查
- **作者**：主理人 + 5 专家团队诊断
- **关联**：继 A1 工程化地基（已完成）之后；依据 `quant-ml-code-audit` skill 的 6 大反模式；后续 B2（回测引擎）、B3（因子 IC/IR）。

---

## 1. 背景与诊断

5 位专家（量化/技术/风控）**独立确认同一根因**：当前 ML 选股的离线指标（AUC/Accuracy）虚高，不反映真实泛化能力。根因是 4 个数据泄露/未来函数反模式，已逐行核验：

| 反模式 | 位置 | 现状代码 |
|--------|------|---------|
| 时序随机切分 | `model_trainer.py:326-339` | `train_test_split(..., random_state=42, stratify=y)` 随机打乱时序 |
| scaler 全量 fit | `model_trainer.py:323+203` | `preprocess_data` 在 split 前，`fit_transform(X)` 含测试集统计量 |
| 未来函数 | `feature_engineering.py:248` | `.fillna(method="bfill").fillna(0)` 用未来值回填 |
| 标签尾部 NaN→0 | `feature_engineering.py:490-497` | `(future_returns > threshold).astype(int)`，末尾 horizon 行 NaN 被标 0 |
| 非平稳特征 | `feature_engineering.py:548-569` | 特征含 `close`（绝对价格）、`OBV`（cumsum 单调递增） |
| **date 未持久化** | `feature_engineering.py:536-542` | 只存 `features_*.npy`/`labels_*.npy`，`all_info`(含 date) 丢失 → 无法时序切分 |

**一句话**：模型在"见过未来 + 末尾错误标签 + 非平稳特征"的数据上训练并用随机切分评估，指标必然虚高。

## 2. 目标（成功标准）

1. **无未来函数**：特征矩阵中无任何由未来值计算/回填的列。
2. **标签正确**：每只股票末尾 `horizon` 行（无未来收益）不进入训练集。
3. **时序切分**：训练/测试按日期划分（训练 < 切分日 ≤ 测试），scaler 仅在训练集 fit。
4. **特征平稳**：去掉绝对价格/累计量，改为平稳化特征。
5. **可验证**：修复后重新训练，**测试集 AUC 明显下降**（预期跌至 0.52-0.58 的真实信号区间）——这是修复成功的标志，不是回归。

## 3. 非目标（YAGNI，留给 B2/B3）

- ❌ 分层回测引擎、交易成本/T+1/涨跌停/退市股 → B2
- ❌ 因子 IC/IR 评估、LightGBM 单调约束 → B3
- ❌ 行业/市值中性化、winsorization 体系 → 后续
- ❌ TimeSeriesSplit 多折交叉验证（B1 用单次按日期切分，简单明确）

## 4. 工作块

### 块 1：feature_engineering.py — 去未来函数 + 修标签 + 平稳化 + 存 date

**1a. 去 bfill（`:248`）**
- 现状：`result = result.fillna(method="bfill").fillna(0)`
- 改为：`result = result.fillna(0)`（仅保留向后填 0；warmup 期前若干行的指标 NaN 由 1b 的 valid_mask 兜底排除）
- 注：彻底方案是 warmup 期 dropna，但去掉 `bfill` 已消除"未来值回填"这一最严重问题；最小改动优先。

**1b. 标签末尾 NaN 不入训练（`:490-513`）**
- 现状：`labels = (future_returns > threshold).astype(int)` 后 `all_labels.extend(labels.tolist())`，末尾 horizon 行 NaN→0 被追加。
- 改为：构造 `valid_mask = future_returns.notna()`；标签、特征、info 都只在 `valid_mask` 为真的行追加。
- 即追加循环加 `if valid_mask.iloc[idx]:` 守卫；标签用 `labels[valid_mask].tolist()`。

**1c. 特征平稳化（`:548-569` `_select_feature_columns`）**
- 从 `feature_patterns` 去掉 `"close"`（绝对价格，非平稳）和 `"OBV"`（cumsum，单调递增）。
- 保留：`MA\d+`、`MACD/DIF/DEA`、`KDJ`、`RSI`、`BOLL_*`、`PDI/MDI/ADX`、`ROC/MAROC`、`BBI`、`rps\d+`（比率/震荡/排名，平稳）。
- 注：去掉 close 不影响技术指标（已计算好）；OBV 留待 B3 改为变化率。

**1d. 持久化 date（`:536` 附近）**
- 新增：`np.save(os.path.join(output_dir, f"dates_{timestamp}.npy"), np.array([info["date"] for info in all_info]))`
- 作用：供 model_trainer 按日期切分。

### 块 2：model_trainer.py — 时序切分 + scaler 隔离 + RF 参数

**2a. 加载 date + 按日期切分**
- `train_models()`（调用 train 的上层）需加载 `dates_*.npy` 并传给 `train()`。
- `train()` 签名增加 `dates: Optional[np.ndarray] = None`。
- 切分逻辑：若 `dates` 提供，按日期排序后取前 `(1-test_size)` 为训练、后 `test_size` 为测试（按时间，不打乱）；否则 fallback 旧逻辑并 warning。

**2b. scaler 仅训练集 fit**
- 重构：切分 → scaler 仅 `fit(X_train)` → `transform(X_train)` + `transform(X_test)`。消除 scaler 泄露。

**2c. RF 参数收紧**
- `model_params`: `max_depth: 20 → 12`，`min_samples_leaf: 1 → 50`，`min_samples_split: 2 → 100`。
- 理由：限制单树深度 + 叶节点最小样本数，抑制过拟合。

### 块 3：验证

1. 重新生成训练数据：管道 `FEATURES` 步（或直接调 `MLTrainingDataGenerator.generate_training_data`）。
2. 重新训练：管道 `TRAIN` 步。
3. **对比修复前后测试集 AUC**：预期从虚高（~0.7+）降至 0.52-0.58。**下降即成功**（坐实此前指标虚高）。
4. 检查：训练数据无 NaN 标签样本、特征无 close/OBV、dates_npy 存在。

## 5. 关键设计决策

- **D1 时序切分方式**：按日期单次切分（训练<切分日≤测试）。简单、可解释、与"样本外"语义一致。TimeSeriesSplit 多折留 B3。
- **D2 date 传递**：新增 `dates_*.npy` 文件。最小侵入，不改 features/labels 的 npy 格式。
- **D3 特征平稳化范围**：仅去 close（绝对价格）+ OBV（cumsum）两个最严重的非平稳量。比率/震荡指标已平稳。行业/市值中性化留后续。
- **D4 标签修复方式**：`valid_mask = future_returns.notna()` 过滤，不追加 NaN 标签样本。比 `iloc[:-horizon]` 更鲁棒（horizon 多档时）。
- **D5 bfill 处理**：改 `fillna(0)`（去未来值回填）。warmup 期样本由 D4 的 valid_mask 自然排除。

## 6. 验收清单

- [ ] `feature_engineering.py:248` 无 `bfill`
- [ ] 训练数据样本数 < 修复前（因排除末尾 NaN 标签行）
- [ ] `dates_*.npy` 生成
- [ ] `model_trainer` 切分按日期（非 random），scaler 仅训练集 fit
- [ ] 特征列无 `close`、`OBV`

## 7. 风险

- **AUC 暴跌被误读为"模型变差"**：需明确这是修复成功标志（此前虚高）。在 commit message 与日志中说明。
- **特征去掉 close 后模型信号变化**：close 本就不是好特征（非平稳），去掉后模型应更稳健。
- **管道兼容**：`train_models` 加载 dates_npy 需与 features_npy 配对；若旧 npy 无 dates，fallback 旧切分 + warning。

## 4. 工作块

### 块 1：版本控制兜底

**做什么**：恢复 `.gitignore`，把全部源码提交进 git，建立可回滚基线。

**怎么做**：
1. 新建 `.gitignore`，分类规则（见 §5 决策 D1）：
   - 忽略：`__pycache__/`、`*.pyc`、`.env`、`market_data/`、`downloads/`、`models/`、`reports/`、`rps_results/`、`training_data/`、`*.log`、`.pytest_cache/`、`.idea/`、`.vscode/`、`.trae/`
   - 保留：所有 `.py`（含 `out/**/*.py`、`back/`、`deep-search/`、`src/`、`tests/`）
2. `git add` 上述源码 + `run_pipeline.py` + `run_pipeline.sh` + `requirement.txt` + `environment.yml`（块 2 产出）+ `.gitignore` + 本设计文档
3. 提交为一个语义化 commit：`feat: 版本化 src/ 数据管道架构与全量源码基线`（**不**沿用 `chore: trigger build` 习惯）

**验证**：
- `git ls-files src/ | wc -l` > 0
- `git status` 干净（或仅剩有意忽略项）
- `git check-ignore .env` 返回 `.env`（确认密钥不进 git）

**风险**：
- 历史日志/数据误入仓库 → 用 `git status` 在 add 前逐一核对，必要时 `git rm --cached`
- 首次提交体量大 → 可接受，是一次性基线

### 块 2：依赖锁定

**做什么**：让"换机器装依赖"从薛定谔态变确定态。

**怎么做**：
1. 从现有可用环境生成 `environment.yml`：
   ```bash
   conda env export -n ashare-llm-analyst --from-history > environment.yml
   ```
   若 `--from-history` 漏关键包（baostock 等），改用 curated 手写 `environment.yml`（列直接依赖 + channel），baostock 若不在 conda channel 则放 `pip:` 段。
2. 重生 `requirement.txt` 为精确锁文件：
   ```bash
   conda run -n ashare-llm-analyst pip freeze > requirement.txt
   ```
   并人工核对必含：`baostock`、`scikit-learn`、`joblib`、`python-dotenv`、`PyYAML`、`akshare`、`seaborn`、`requests`、`openai`、`pandas`、`numpy`、`matplotlib`。
3. 在 `environment.yml` 顶部注释说明：conda 环境名为 `ashare-llm-analyst`，与 `run_pipeline.sh:280`、`src/core/config.py` 一致。

**验证**（强验收）：
```bash

conda run -n ashare-llm-analyst-test python -c "import src.data.pipeline; import baostock, sklearn, joblib, dotenv, yaml, akshare; print('OK')"
```

**风险**：
- `conda env export` 含平台/路径特定内容（如 `prefix:`）→ 手工剔除 `prefix:` 行

## 5. 关键设计决策

**D1：`out/` 在 git 中的命运（最重要决策）**
- 旧 `.gitignore` 的 `out/` 会忽略整个目录，导致 `out/04-stock-analysis.py` 等仍在用的源码永远丢失。
- **决策**：保留 `out/**/*.py`（及 `back/`、`deep-search/*.py`）进 git；仅忽略 `out/` 下的数据/日志/报告/缓存子目录（`out/market_data/`、`out/reports/`、`out/logs/`、`out/models/`、`out/training_data/`、`out/downloads/`、`out/rps_results/`、`out/charts/` 等）。
- **理由**：方向 B/C 专家的诊断与修复大量基于 `out/` 文件（如 `out/04-stock-analysis.py:248` 的未来函数、`out/MyTT_optimized.py`）；现在删掉会丢失修复锚点。冗余清理留给架构合并阶段。

**D2：依赖工具选 conda `environment.yml` 而非 pip-tools/poetry**
- 项目已用 conda（`run_pipeline.sh:280` 硬编码 `conda activate ashare-llm-analyst`），conda 是既成事实。
- baostock 等包在 conda 环境里已验证可用。
- **决策**：`environment.yml`（curated 直接依赖）为主 + `requirement.txt`（`pip freeze` 锁文件）为精确复现补充。

**D3：范围严格限于"止血"，不碰业务**
- 数据泄露/未来函数/财报伪数据虽是更严重的业务问题，但它们需要"能跑、能回滚、能验证"的工程地基才能安全修复。
- **决策**：A1 只建安全网，业务修复严格留给方向 B/C。
